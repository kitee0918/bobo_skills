# 架构模板 — 按项目类型

> 此文件为 `proj-flow` skill 的参考文档。Agent 在 Step 2 中根据项目类型选择对应模板。

---

## 类型1：Web全栈应用

适用：前后端分离的 Web 应用（React/Vue + Express/Spring + Database）

### 架构分层

```
┌─────────────────────────────────────────┐
│              前端 SPA / SSR              │
│  页面路由 | 状态管理 | API Client       │
└─────────────────┬───────────────────────┘
                  │ REST/GraphQL (JSON)
                  ▼
┌─────────────────────────────────────────┐
│              后端 API 层                 │
│  ┌──────────┐  ┌──────────┐             │
│  │ 路由层    │→ │ 服务层    │→ ┌──────┐  │
│  │ (HTTP入口)│  │ (业务编排)│  │模型层 │  │
│  └──────────┘  └──────────┘  │(CRUD) │  │
│                  │           └───┬──┘  │
│                  ▼               ▼      │
│            ┌──────────┐    ┌────────┐   │
│            │ 集成层    │    │ 数据库  │   │
│            │ (外部API) │    │        │   │
│            └──────────┘    └────────┘   │
└─────────────────────────────────────────┘
```

### 必须覆盖的章节

| 章节 | 内容要点 |
|------|---------|
| **架构总览** | 分层图 + 层间数据流方向 |
| **技术选型表** | 运行时/框架/数据库/缓存/日志/文件存储 |
| **数据模型** | ER图 + 每张表关键字段 + 外键关系 + 状态枚举 |
| **API路由表** | 方法 + 路径 + 功能 + 请求/响应格式 |
| **核心数据流** | 2-4条业务流程的步骤序列（如：用户注册→验证→入库） |
| **前后端交互协议** | API base URL、认证方式（JWT/Session）、错误码约定 |
| **目录结构** | 完整的 server/ 和 client/ 目录树 |
| **错误处理** | 各层异常处理约定（路由层→服务层→集成层→全局） |
| **日志策略** | 日志分类、级别、存储位置 |

### 阶段拆分建议

| 阶段 | 内容 | 预计 |
|------|------|------|
| 0 | 项目骨架 + 依赖 + 构建脚本 + 数据库建表 | 1-2天 |
| 1 | 数据模型 + 种子数据 + 数据迁移 | 1-3天 |
| 2A | 核心服务层（业务逻辑） | 2-4天 |
| 2B | 集成层（外部API） | 1-2天 |
| 3 | API路由层 | 2-3天 |
| 4A | 前端骨架 + 基础页面 | 2-3天 |
| 4B | 前端剩余页面 + 交互 | 3-5天 |
| 5 | 集成测试 + 收尾 | 2-3天 |

## 类型2：REST/GraphQL纯API服务

适用：只有后端API，无前端界面（被其他服务或移动端调用）

### 架构分层

```
┌─────────────────────────────────────────┐
│              客户端（外部）               │
└─────────────────┬───────────────────────┘
                  │ REST/GraphQL (JSON)
                  ▼
┌─────────────────────────────────────────┐
│              中间件链                     │
│  认证 | 限流 | 日志 | CORS | 压缩        │
└─────────────────┬───────────────────────┘
                  ▼
┌─────────────────────────────────────────┐
│  ┌──────────┐  ┌──────────┐             │
│  │ 路由层    │→ │ 服务层    │→ ┌──────┐  │
│  └──────────┘  └──────────┘  │模型层 │  │
│                               └───┬──┘  │
│                                   ▼      │
│                              ┌────────┐   │
│                              │ 数据库  │   │
│                              └────────┘   │
└─────────────────────────────────────────┘
```

### 必须覆盖的章节

| 章节 | 内容要点 |
|------|---------|
| **架构总览** | 分层图 + 中间件链位置 |
| **技术选型表** | 运行时/框架/数据库/缓存/API文档工具 |
| **认证方案** | JWT/OAuth2/API Key 的签发、验证、刷新流程 |
| **数据模型** | ER图 + 表定义 |
| **API路由全表** | 分组（资源名）+ 方法 + 路径 + 权限 + 请求/响应 Schema |
| **中间件链** | 每个中间件的顺序、职责、失败行为 |
| **错误码体系** | HTTP状态码 + 业务错误码 + 错误消息格式 |
| **目录结构** | server/ 目录树 |
| **部署架构** | 进程模型、端口、健康检查端点 |

### 阶段拆分建议

| 阶段 | 内容 |
|------|------|
| 0 | 骨架 + 中间件 + 数据库建表 |
| 1 | 数据模型 + 种子数据 |
| 2 | 服务层（业务逻辑） |
| 3 | 路由层（全部端点） |
| 4 | 认证 + 限流 + API文档 |
| 5 | 集成测试 + 收尾 |

## 类型3：CLI命令行工具

适用：终端命令工具、脚本集合、开发工具链

### 架构分层

```
┌─────────────────────────────────────────┐
│              CLI 入口 (main)              │
│  参数解析 | 配置加载 | 帮助输出          │
└─────────────────┬───────────────────────┘
                  ▼
┌─────────────────────────────────────────┐
│              命令路由                     │
│  ┌──────┐  ┌──────┐  ┌──────┐           │
│  │ cmd A │  │ cmd B │  │ cmd C │  ...    │
│  └──┬───┘  └──┬───┘  └──┬───┘           │
│     │         │         │                │
│     ▼         ▼         ▼                │
│  ┌──────────────────────────┐            │
│  │        核心逻辑层         │            │
│  └──────────────────────────┘            │
└─────────────────┬───────────────────────┘
                  ▼
┌─────────────────────────────────────────┐
│           基础设施                        │
│  文件IO | HTTP Client | 格式化输出       │
└─────────────────────────────────────────┘
```

### 必须覆盖的章节

| 章节 | 内容要点 |
|------|---------|
| **命令树** | 完整的命令+子命令层级结构 |
| **参数设计** | 每个命令的参数名、类型、必需/可选、默认值、互斥关系 |
| **配置层级** | 默认值 → 配置文件 → 环境变量 → 命令行参数 的覆盖优先级 |
| **I/O规范** | stdin/stdout/stderr 的约定、输出格式（JSON/表格/纯文本） |
| **退出码规范** | 0=成功、1=一般错误、2=参数错误、... |
| **目录结构** | src/ bin/ config/ test/ |
| **安装与分发** | npm/pip/cargo 发布方式、全局安装方法 |

### 阶段拆分建议

| 阶段 | 内容 |
|------|------|
| 0 | 骨架 + 参数解析 + 帮助系统 |
| 1 | 核心命令实现 |
| 2 | 配置管理 + 输出格式化 |
| 3 | 边缘命令 + 错误处理完善 |
| 4 | 测试 + 文档 + 发布 |

## 类型4：库/SDK/框架

适用：供其他项目引用的 npm/pip/cargo 包

### 架构分层

```
┌─────────────────────────────────────────┐
│              公开 API 面                  │
│  (index.js / __init__.py / lib.rs)       │
│  只暴露用户应该使用的符号                 │
├─────────────────────────────────────────┤
│              内部实现                     │
│  ┌──────┐  ┌──────┐  ┌──────┐           │
│  │模块A │  │模块B │  │模块C │           │
│  └──┬───┘  └──┬───┘  └──┬───┘           │
│     │         │         │                │
│     └─────────┼─────────┘                │
│               ▼                          │
│  ┌──────────────────────────┐            │
│  │       内部工具层          │            │
│  └──────────────────────────┘            │
└─────────────────────────────────────────┘
```

### 必须覆盖的章节

| 章节 | 内容要点 |
|------|---------|
| **公开API面** | 所有 export/public 符号列表 + 签名 + 文档 |
| **模块依赖图** | 内部模块间的依赖关系（禁止循环依赖） |
| **设计模式** | 工厂/Builder/策略/插件 等关键模式的使用位置 |
| **扩展机制** | 用户如何扩展/定制（插件、中间件、hook、事件） |
| **版本策略** | SemVer 约定、Breaking Change 管理 |
| **错误处理** | 自定义错误类层级、何时 throw vs 返回 error |
| **目录结构** | src/ test/ examples/ docs/ |
| **TypeScript 类型（如适用）** | 类型导出策略 |

### 阶段拆分建议

| 阶段 | 内容 |
|------|------|
| 0 | 骨架 + 构建配置 + 测试框架 |
| 1 | 核心API实现 |
| 2 | 扩展机制 + 工具层 |
| 3 | 文档 + 示例代码 + TypeScript类型 |
| 4 | 边缘场景测试 + 发布 |

## 类型5：数据处理管道

适用：ETL、流处理、批量数据处理、报表生成

### 架构分层

```
┌─────────────────────────────────────────┐
│              数据源层                     │
│  DB Reader | API Fetcher | File Scanner  │
│  CSV Parser | PDF Extractor | ...        │
└─────────────────┬───────────────────────┘
                  ▼
┌─────────────────────────────────────────┐
│              转换/处理层                  │
│  ┌──────┐  ┌──────┐  ┌──────┐           │
│  │Stage1│→ │Stage2│→ │Stage3│→ ...      │
│  └──────┘  └──────┘  └──────┘           │
│        ↓ 失败                             │
│  ┌──────────────────────────┐            │
│  │     错误队列 + DLQ        │            │
│  └──────────────────────────┘            │
└─────────────────┬───────────────────────┘
                  ▼
┌─────────────────────────────────────────┐
│              输出/汇层                    │
│  DB Writer | File Exporter | API Sender  │
└─────────────────────────────────────────┘
```

### 必须覆盖的章节

| 章节 | 内容要点 |
|------|---------|
| **阶段拓扑图** | 处理管道的有向无环图（DAG） |
| **数据Schema** | 每个阶段的输入/输出数据格式定义 |
| **错误处理** | 单条失败策略（跳过/重试/中止）、死信队列DLQ设计 |
| **幂等性策略** | 如何确保重复执行不产生副作用 |
| **性能与资源** | 并发控制、内存限制、批处理大小 |
| **调度方式** | 手动触发 / Cron / 事件驱动 / 持续运行 |
| **监控** | 处理进度、成功率、延迟指标 |

### 阶段拆分建议

| 阶段 | 内容 |
|------|------|
| 0 | 骨架 + 数据源连接器 |
| 1 | 核心转换逻辑 |
| 2 | 错误处理 + 重试 + DLQ |
| 3 | 输出/汇 + 调度 |
| 4 | 监控 + 测试 + 收尾 |

## 类型6：移动端App

适用：iOS/Android 原生或 React Native/Flutter 跨平台

### 架构分层

```
┌─────────────────────────────────────────┐
│              UI 层                        │
│  页面 | 组件 | 导航栈 | 主题             │
└─────────────────┬───────────────────────┘
                  ▼
┌─────────────────────────────────────────┐
│              状态管理层                   │
│  Redux/MobX/Provider/BLoC/Zustand       │
└─────────────────┬───────────────────────┘
                  ▼
┌─────────────────────────────────────────┐
│              数据层                       │
│  ┌──────────┐  ┌──────────┐             │
│  │ API Client│  │ 本地存储  │             │
│  └──────────┘  └──────────┘             │
└─────────────────────────────────────────┘
```

### 必须覆盖的章节

| 章节 | 内容要点 |
|------|---------|
| **页面路由栈** | 所有页面 + 导航关系图（Tab/Stack/Modal） |
| **状态管理架构** | 全局状态 vs 局部状态、数据流方向 |
| **离线存储策略** | 本地数据库选型、同步冲突解决 |
| **推送通道** | APNs/FCM 或第三方推送方案 |
| **平台适配** | 哪些逻辑共用、哪些平台特化、平台判断方式 |
| **API通信** | Base URL、认证Token存储、网络错误处理 |
| **目录结构** | src/screens/ components/ services/ store/ |

### 阶段拆分建议

| 阶段 | 内容 |
|------|------|
| 0 | 项目初始化 + 导航骨架 |
| 1 | API Client + 状态管理 + 本地存储 |
| 2 | 核心页面实现 |
| 3 | 推送 + 离线 + 平台适配 |
| 4 | 剩余页面 + 测试 + 收尾 |

## 类型7：静态网站/文档站

适用：博客、文档站、Landing Page、SSG站点

### 架构分层

```
┌─────────────────────────────────────────┐
│              页面路由树                   │
│  / → /docs/ → /docs/xxx → /blog/ → ...  │
├─────────────────────────────────────────┤
│              布局 / 组件                  │
│  Layout | Nav | Footer | MDX Renderer   │
├─────────────────────────────────────────┤
│              数据源                       │
│  Local MDX | Headless CMS | REST API    │
├─────────────────────────────────────────┤
│              构建输出                     │
│  Static HTML + CSS + JS (CDN-ready)     │
└─────────────────────────────────────────┘
```

### 必须覆盖的章节

| 章节 | 内容要点 |
|------|---------|
| **页面路由树** | 所有路由 + 对应的数据源 |
| **数据源设计** | 内容来源（文件/API/CMS）、内容Schema |
| **组件层级** | Layout→Section→Component 的嵌套关系 |
| **构建流程** | 构建步骤、优化策略（图片/字体/代码分割） |
| **SEO策略** | meta 标签生成、sitemap、结构化数据 |
| **部署目标** | CDN/静态托管（Vercel/Netlify/GitHub Pages） |
| **目录结构** | pages/ components/ content/ public/ |

### 阶段拆分建议

| 阶段 | 内容 |
|------|------|
| 0 | 框架初始化 + 基础布局 |
| 1 | 内容数据源对接 |
| 2 | 核心页面 + 组件 |
| 3 | SEO + 性能优化 |
| 4 | 测试 + 部署配置 + 收尾 |

## 类型8：微服务/云函数

适用：Serverless 函数、微服务集群

### 架构分层

```
┌─────────────────────────────────────────┐
│              API 网关 / 路由器            │
│  认证 | 限流 | 路由 | 聚合              │
└─────┬──────────┬──────────┬─────────────┘
      │          │          │
      ▼          ▼          ▼
┌──────────┐ ┌──────────┐ ┌──────────┐
│ 服务 A    │ │ 服务 B    │ │ 服务 C    │
│ (独立部署) │ │ (独立部署) │ │ (独立部署) │
└────┬─────┘ └────┬─────┘ └────┬─────┘
     │            │            │
     └────────────┼────────────┘
                  ▼
┌─────────────────────────────────────────┐
│          共享基础设施                     │
│  消息队列 | 配置中心 | 服务发现          │
└─────────────────────────────────────────┘
```

### 必须覆盖的章节

| 章节 | 内容要点 |
|------|---------|
| **服务拆分边界** | 每个服务的职责、所属业务域、边界上下文 |
| **通信协议** | 同步（HTTP/gRPC）vs 异步（消息队列/事件）的选择规则 |
| **数据所有权** | 每个服务独占哪些数据、跨服务查询方案（API组合/CQRS） |
| **服务发现** | 服务注册、健康检查、负载均衡 |
| **部署单元** | 每个服务的部署方式（容器/函数）、资源配置 |
| **错误隔离** | 熔断器、超时、重试、降级策略 |
| **目录结构** | 单仓（monorepo packages/）还是多仓 |

### 阶段拆分建议

| 阶段 | 内容 |
|------|------|
| 0 | 项目骨架（monorepo）+ 共享库 |
| 1 | 第一个核心服务（端到端走通） |
| 2 | 其余服务实现 |
| 3 | 网关 + 服务发现 + 错误隔离 |
| 4 | 集成测试 + 部署配置 + 收尾 |
