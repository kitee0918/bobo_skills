# Project Init — 项目全生命周期管理

统一入口，覆盖从项目初始化到阶段收尾的完整开发流程。所有详细工作流存放在 `sub/` 目录下，按需读取。

---

## 目录结构

```
proj-flow/
├── SKILL.md              ← 本文件（调度器）
├── sub/
│   ├── shared.md         ← 共享纪律：neat-freak / git commit / 上下文压缩 / 阶段命名
│   ├── init.md           ← 项目初始化五步工作流（Step1-5）
│   ├── plan.md           ← 需求整理与排序六步工作流
│   ├── executing.md      ← 阶段执行管理（逐阶段确认）
│   └── wrap.md           ← 阶段收尾五步清单
├── templates/
│   └── architecture.md   ← 8种项目类型架构模板
└── req_template.md       ← 需求填写模板（[NEW]/[FIX]/[Q]）
```

---

## 意图识别与子文件路由

Agent 收到用户消息后，按触发词识别意图，**仅读取对应子文件**：

### 场景 A：项目初始化

**触发词**：`初始化项目` `新建项目` `从零开始` `项目初始化` `create a new project` `scaffold a project`

**行为**：读取 `sub/init.md` 获取五步初始化工作流。如涉及大型项目架构设计，另读取 `templates/architecture.md`。

### 场景 B：需求整理与排序

**触发词**：`整理需求` `需求排序` `排一下需求` `需求计划` `任务拆解` `规划任务` `整理依赖`

**行为**：读取 `sub/plan.md` 获取六步需求整理工作流。输出 todo_write 计划后自动衔接 `sub/executing.md`。

### 场景 C：阶段执行管理

**触发词**：`开始执行` `执行阶段` `继续执行` `开始开发`

**行为**：读取 `sub/executing.md` 获取逐阶段确认流程。每个阶段完成后自动衔接 `sub/wrap.md`。

### 场景 D：阶段收尾

**触发词**：`阶段完成` `收尾` `阶段收尾` `这个阶段做完了` `验证清单` `连招收尾` `连招整理`

**行为**：读取 `sub/wrap.md` 获取五步收尾清单。

## 共享纪律（所有场景通用）

所有子文件共同引用的纪律规范集中在 `sub/shared.md`：

| 章节 | 内容 |
|------|------|
| 一 | neat-freak 联动规则（触发场景 + 触发方式） |
| 二 | git commit 纪律（命令 + 格式 + 提交策略） |
| 三 | 上下文压缩策略（长程任务判定 + 压缩流程 + 阈值） |
| 四 | 阶段与任务命名约定（stage_N / task_N + 阶段划分 + 复杂度评分） |
| 五 | 触发词 → 子文件映射表（本文件的路由速查） |

> 任何子文件头部均有 `> 共享纪律详见 sub/shared.md` 提示。Agent 在首次执行某场景时应同时读取 `sub/shared.md`。

## 子组件间的流转关系

```
sub/init.md ──(项目已存在)──→ sub/plan.md
                                   │
                              (输出计划)
                                   │
                                   ▼
                            sub/executing.md
                              │            │
                         (阶段完成)   (追加减需)
                              │            │
                              ▼            ▼
                            sub/wrap.md   sub/plan.md
                              │
                         (收尾完成)
                              │
                              ▼
                            sub/executing.md（继续下一阶段）
```

## 补充说明

- **首次使用**：Agent 应至少读取 `sub/shared.md` + 目标子文件，建立对整体纪律的认知
- **逃生口**：若当前项目已有部分文档，Agent 应检查已有内容，只补全缺失步骤
- **hr-project-ops**：与本 skill 互补 — hr-project-ops 侧重 HR 项目具体操作（手动测试指引、UI修改模式、导入导出规范），本 skill 侧重通用流程管理
