# 阶段收尾 — 五步清单

> 此文件为 `proj-flow` skill 的子组件。Agent 在收到收尾类触发词后应读取此文件。
> 共享纪律（neat-freak、git commit）详见 `sub/shared.md`。

---

## 概述

当一个开发阶段或子任务组完成时，按本清单逐项执行标准化收尾，确保代码质量、文档一致性和版本追溯。

**适用项目**：任何有构建流程、测试套件和版本控制的项目。

**核心能力**：
- **构建验证**：确保前端/后端编译通过
- **回归测试**：运行全量测试确认无回归
- **文档同步**：联动 neat-freak 审查文档与记忆一致性
- **版本提交**：规范化 git commit

---

## 收尾清单（5 步，不可跳过）

### 第 1 步：代码构建验证

执行项目构建命令，确认无编译错误：

```bash
# 前端构建（示例）
cd client && npm run build

# 或后端构建
npm run build
```

> **通过标准**：构建零 warning、零 error。
>
> 具体构建命令需根据项目实际配置调整。

### 第 2 步：回归测试

运行项目定义的测试套件：

```bash
# 示例：按顺序执行多个测试
node server/testServiceLayer.js
node server/testRoutes.js
node server/testPhase5.js
```

> **通过标准**：所有测试项 PASS，0 失败。
>
> 具体测试命令和文件路径需根据项目实际配置调整。对于没有测试套件的项目，至少执行一次手动冒烟测试覆盖核心流程。

### 第 3 步：neat-freak 文档同步

触发 neat-freak 完成以下同步：

1. 项目文档一致性审查（`README.md`、`docs/`、`.qoder/` 配置等）
2. Agent 记忆同步（阶段进度、关键决策）
3. 过期信息清理

> neat-freak 联动规则和触发方式详见 `sub/shared.md` 第一章。

### 第 4 步：更新项目文档

确认以下文档反映最新状态：

| 文档 | 需更新内容 |
|------|-----------|
| 项目阶段状态文档 | 当前阶段、已完成阶段、完成日期 |
| 架构/设计文档 | 如有新增 API、数据模型变更 |
| 变更日志 | 本轮改动的简要说明 |

> 具体文档路径和名称因项目而异。关键原则：任何可能被后续开发者参考的文档都应保持最新。

### 第 5 步：git commit

> git commit 纪律详见 `sub/shared.md` 第二章。

---

## 收尾完成标志

全部 5 步完成后，输出确认信息：

```
✅ 阶段收尾完成！
  - 代码构建：通过
  - 回归测试：X/X 通过
  - neat-freak：文档与记忆已同步
  - 项目文档：已更新
  - git commit：已提交

下一阶段可开始。
```

---

## 异常处理

| 异常情况 | 处理方式 |
|---------|---------|
| 构建失败 | 修复编译/构建错误 → 重新执行第 1 步 |
| 测试有失败项 | 修复代码 → 重新执行第 2 步 |
| neat-freak 无法执行 | 手动检查文档和记忆，标记为「手动同步」 |
| 无新增变更（纯讨论阶段） | 跳过第 5 步 git commit，其余照常执行 |
| 项目无测试套件 | 第 2 步改为手动冒烟测试，覆盖核心流程 |

## 与其他子组件的关系

```
sub/plan.md → sub/executing.md → sub/wrap.md（本文件）
                                      │
                                      └──(完成后)：回 sub/executing.md 继续下一阶段
```

- 上游：`sub/executing.md` 在阶段完成后触发本文件
- 下游：收尾完成后回到 `sub/executing.md`，继续下一阶段或结束
- 独立调用：用户直接说「收尾」时，独立执行本清单
