# 共享纪律 — neat-freak / git / 上下文压缩 / 阶段命名

> 此文件为 `proj-flow` skill 的子组件，被 `init.md`、`plan.md`、`executing.md`、`wrap.md` 共同引用。
> 任何子文件中出现「详见 shared.md」即指此文件。

---

## 一、neat-freak 联动规则

以下场景**必须**触发 neat-freak 进行文档与记忆同步：

| 场景 | 触发条件 | 说明 |
|------|---------|------|
| 阶段收尾 | 每个开发阶段完成 | 执行收尾清单中的 neat-freak 步骤 |
| 子任务组完成 | 每完成一组有依赖关系的任务 | agent 需在子任务组最后一个任务完成后调用 neat-freak |
| 上下文过长 | 当前会话待办项 ≥6 且已完成 3-4 项 | 主动触发 neat-freak 压缩上下文 |
| 用户主动要求 | 说「同步一下」「整理文档」「梳理一下」「收尾」等 | 直接触发 neat-freak |

**触发方式**：agent 调用 `Skill` 工具执行 `neat-freak`。

> 如果 neat-freak 不可用，手动检查项目文档和 agent 记忆，标记为「手动同步」。

## 二、git commit 纪律

### 提交命令

```bash
git add -A
git commit -m "<一句话中文总结本轮改动>"
```

### commit message 格式

`{阶段号/标识} {简短描述}`，示例：
- `12.1 快速修复：占位符清洗 + 交互优化`
- `v1.3 新增批量删除功能`
- `bugfix: 修复导出按钮无响应`

### 提交策略

| 场景 | 行为 |
|------|------|
| 每个阶段完成 | 必须 git commit |
| 阶段间隔 <30min 或变更 <2 文件 50 行 | 建议与上一阶段合并提交 |
| 连续跳过上限 2 次 | 第 3 次强制提交 |
| 无新增变更（纯讨论） | 跳过 git commit |
| 无未提交变更 | neat-freak + 总结，跳过 git commit |

## 三、上下文压缩策略

### 触发条件

当前规划的任务列表中待办项 ≥6 项时，视为长程任务。

### 自动压缩流程

每完成 3-4 个待办项后，**必须主动执行一次上下文压缩**：

1. 调用 `Skill` 工具执行 `neat-freak`，触发记忆同步和文档一致性审查
2. 待 neat-freak 完成后，review 当前 todo 列表，确认进度和下一步目标
3. 用简短语言重新向自己确认：「当前已完成 X/Y 项，剩余任务为...」
4. 继续执行后续任务

### 上下文大小阈值

| 阈值 | 行为 |
|------|------|
| 上下文 < 150KB | 正常运行 |
| 上下文 150KB-200KB | 建议执行 neat 连招（neat-freak + 一句话总结 + git commit） |
| 上下文 > 200KB | 强制执行 neat 连招 |

> Agent 每完成 3 个任务后估算一次上下文大小。

### 目的

- 压缩已消耗的对话上下文，释放空间
- 将已完成工作的关键结论写入记忆，不至于丢失
- 保持 Agent 对剩余任务的清醒认知

## 四、阶段与任务命名约定

### todo_write ID 规范

| 前缀 | 含义 | 示例 |
|------|------|------|
| `stage_N` | 阶段分隔符 | `stage_0`、`stage_1`、`stage_A` |
| `task_N` | 具体任务 | `task_1`、`task_2` |

每个 `stage_N` 管辖其后直到下一个 `stage` 之前的所有任务。按原始顺序执行，不重排。

### 阶段划分建议

| 阶段类型 | 条件 |
|---------|------|
| 快速修复 | 复杂度 ≤2 且无依赖的 `[FIX]` 任务 |
| 页面优化 | 同页面/同模块的前端改动聚合 |
| 后端修复 | 后端路由/服务层纯后端改动 |
| 功能升级 | `[NEW]` 类新功能 |
| 收尾 | `[Q]` 类说明 + 全量回归测试 |

### 复杂度评分

| 分数 | 定义 | 典型特征 |
|------|------|---------|
| ⭐ (1) | 单行/单文件微调 | 改一个常量、文案、CSS |
| ⭐⭐ (2) | 单文件多处修改 | 一个组件内调整交互逻辑 |
| ⭐⭐⭐ (3) | 跨文件修改 | 改后端+前端、涉及数据流 |
| ⭐⭐⭐⭐ (4) | 新增依赖+跨层改动 | 安装新包、新增路由、改模型 |
| ⭐⭐⭐⭐⭐ (5) | 架构级变动 | 数据迁移、协议变更、重构 |
