# 阶段执行管理

> 此文件为 `proj-flow` skill 的子组件。Agent 在收到执行类触发词后应读取此文件。
> 共享纪律（neat-freak、git commit、上下文压缩）详见 `sub/shared.md`。

---

## 概述

连接 `sub/plan.md`（规划）与 `sub/wrap.md`（收尾），管理项目逐阶段执行环节。

**核心职责**：每阶段完成后暂停，等待用户确认再推进。

辅助能力：上下文监控、提交建议。全程后台静默，仅在需要决策时介入。

---

## 激活

`sub/plan.md` 输出 todo_write 计划后自动激活，或用户说「开始执行」时激活。

---

## 计划识别

解析 todo_write：`id` 以 `stage_` 开头 = 阶段分隔符，`task_` 开头 = 任务。每个 `stage_N` 管辖其后直到下一个 `stage` 之前的所有任务。按原始顺序执行，不重排。

---

## 阶段执行确认（核心）

一个阶段内所有任务标记 COMPLETE 后，Agent 输出：

```
✅ 阶段「{名称}」已完成（{N}/{N} 任务）。

📋 下一步：
  [A] 继续下一阶段
  [B] 先手动测试
  [C] 追加需求/问题（将重新调用 sub/plan.md 排序）
  [D] 暂停

请输入 A/B/C/D：
```

等待用户明确选择后才继续。最后一个阶段时 [A] 变为「执行收尾流程（sub/wrap.md）」。

---

## 辅助机制

- **上下文监控**：每 3 个任务估算一次，阈值和压缩策略详见 `sub/shared.md` 第三章。
- **提交建议**：阶段间隔 <30min 或变更 <2 文件 50 行，建议合并提交。连续跳过上限 2 次，第 3 次强制。详见 `sub/shared.md` 第二章。
- **静默模式**：仅阶段确认、上下文预警、提交建议时输出，其余全程静默。

---

## 异常处理

| 情况 | 处理 |
|------|------|
| 用户追加减需 | 暂停 → 读取 `sub/plan.md` 重排 → 更新计划 |
| 无未提交变更 | neat-freak + 总结，跳过 git commit |
| 收尾失败 | 暂停，等待修复后重新触发 `sub/wrap.md` |

---

## 与其他子组件的关系

```
sub/plan.md ──(输出计划)──→ sub/executing.md（本文件）──(阶段完成)──→ sub/wrap.md
                                  ↑                                      │
                                  └──(追加减需：回 plan.md)──────────────┘
```

- 上游：`sub/plan.md` 输出 todo_write 计划后进入本文件
- 下游：每个阶段完成后可触发 `sub/wrap.md` 收尾
- 回环：用户追加减需时，回 `sub/plan.md` 重排计划
